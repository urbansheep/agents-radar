## 1. Панорама экосистемы

Экосистема AI CLI-инструментов находится в фазе активного роста с одновременным накоплением технического долга: все пять инструментов зафиксировали интенсивную активность сообщества без единого стабильного релиза за сутки, что указывает на высокое давление со стороны запросов при дефиците пропускной способности мейнтейнеров. Доминирующие боли повторяются независимо от вендора — нестабильность на Windows, проблемы с хуками и непредсказуемость расходов на токены, — что свидетельствует о системных разрывах в зрелости платформы, а не об индивидуальных упущениях команд. Параллельно прослеживается отчётливый сдвиг от монолитного агента к мультиагентной архитектуре: все крупные игроки одновременно строят Teams/Subagents/Modes-инфраструктуру. Вопрос монетизации и доступности выходит из тени: региональное ценообразование и прозрачность расходов становятся конкурентными дифференциаторами, а не опциональными фичами. Разрыв между CLI-опытом и IDE-интеграцией остаётся хронической болью аудитории и всё активнее адресуется через VS Code Companion / ACP-протоколы.

## 3. Общие функциональные направления

Следующие направления фиксируются одновременно в нескольких инструментах, что указывает на отраслевые императивы, а не частные запросы.

### 🪟 Нестабильность на Windows
**Claude Code** (#24918, #27801, #28892), **OpenAI Codex** (#13031, #13148), **Gemini CLI** (#18896, #20217), **OpenCode** (#5046, #15480), **Qwen Code** (#2007)

Системная проблема платформы. Windows-пользователи во всех инструментах получают деградированный опыт: сбои виртуализации, порча EOL, мерцание интерфейса, невозможность копирования текста. Паттерн повторяется вне зависимости от стека (Electron, Node.js, Python).

### 🪝 Ненадёжность системы хуков
**Claude Code** (#29799, #16282), **Gemini CLI** (#20439), **Qwen Code** (#1708)

Хуки — ключевой механизм автоматизации и мониторинга — работают непредсказуемо: не срабатывают при non-zero exit code, вызывают бесконечные циклы при retry, игнорируются в `settings.json`. Проблема блокирует корпоративные CI/CD-сценарии.

### 🤖 Мультиагентная архитектура и специализированные режимы
**OpenAI Codex** (PR #13155, #13156 — Teams/task tools), **Gemini CLI** (эпики Remote Agents #20302–#20304, Local Subagents), **Qwen Code** (PR #1980 — Modes Layer), **OpenCode** (PR #15557 — GitLab DAP)

Все ключевые инструменты одновременно строят инфраструктуру для мультиагентности. Это не совпадение — рынок движется к оркестрации агентов как к стандартному примитиву.

### 🔌 Плагинная экосистема и именование навыков
**Claude Code** (PR #29757, #29731 — kebab-case для skills), **OpenAI Codex** (PR #12864 — PluginsManager), **Gemini CLI** (MCP-интеграция), **Qwen Code** (PR #1975 — `qwen mcp enable/disable`)

Документация по разработке плагинов недостаточна или вводит в заблуждение во всех инструментах. Naming conventions, порядок загрузки, sandbox-разрешения — точки трения для авторов расширений.

### 💸 Прозрачность расходов и региональное ценообразование
**Claude Code** (#17432 — INR-цены, #29810 — неожиданные расходы, #29550 — исчезновение Haiku-вызовов), **OpenCode** (#15555 — таймауты, ведущие к повторным запросам)

Пользователи хотят понимать, за что платят. Неожиданные всплески расходов и отсутствие локализованных тарифов становятся барьерами для глобального масштабирования.

### 🌐 Headless/SSH и корпоративная надёжность
**Kimi Code CLI** (#1293), **Gemini CLI** (#20058 — Policy Engine в headless), **OpenCode** (#15558 — exit code при ошибке), **OpenAI Codex** (#13154 — игнорирование AGENTS.md)

CLI-инструменты разрабатывались в расчёте на интерактивное использование и системно не готовы к CI/CD и серверным окружениям. Запрос на предсказуемое поведение в неинтерактивном режиме нарастает.

### ♿ Доступность и локализация
**Claude Code** (#29811 — RTL-регрессия иврит/арабский), **Gemini CLI** (PR #20750 — screen reader для RewindViewer), **Qwen Code** (#2032 — пробелы в Chinese-именах, #2022 — локализация отчётов), **OpenCode** (#15561 — Unicode-пути в TUI)

Интернационализация остаётся ахиллесовой пятой: локализационные регрессии вводятся с каждым крупным обновлением, а CJK и RTL-пользователи системно получают худший опыт.

## 4. Дифференциация

| Измерение | Claude Code | OpenAI Codex | Gemini CLI | Kimi Code CLI | OpenCode | Qwen Code |
|---|---|---|---|---|---|---|
| **Целевая аудитория** | IDE-разработчики (VS Code) + корпоративный сегмент | API-разработчики, power-users | Широкая: от CLI до enterprise | ML-инженеры, DevOps | Разработчики, ориентированные на мультипровайдерность | CJK-аудитория + энтерпрайз |

| **Архитектурный фокус** | Cowork (VM-окружение), Skills/Plugins | Агентные команды, Teams, Resumable rollout | Remote/Local Subagents, Plan Mode | Компактность, SSH/proxy | Мультипровайдерность, MCP | Modes Layer, VibeGuard, CJK |
| **Подход к безопасности** | Push-guardrails (PR #29732) | Sandbox permissions для skills | Policy Engine, yolo-mode trust | Proxy через env-переменные | VibeGuard-редакция, exit-code контроль | Client-side redaction (PR #2031) |
| **Зрелость плагинной модели** | Skills в начальной стадии, документация слабая | PluginsManager — ранний MVP | MCP как основной стандарт | Минимальная | Множественные file:// плагины, OAuth MCP | MCP + встроенные Modes |
| **Болевая точка #1** | Windows Cowork + RTL-регрессия | WebSocket нестабильность + Auth 401 | Headless надёжность + Windows мерцание | SSH/headless + зависания агентов | Утечка памяти + провайдерная совместимость | CJK-обработка + bash tool naming |

**Ключевые стратегические различия:**

- **Claude Code** делает ставку на изолированное VM-окружение (Cowork) — уникальный подход, но именно это становится источником наибольшего числа критических сбоев.
- **OpenAI Codex** наиболее агрессивно строит мультиагентную оркестрацию (Teams, task tools) — три связанных PR от одного автора за сутки.
- **Gemini CLI** имеет наибольшую активность и наиболее структурированный roadmap (спринтовые эпики), но накопил значительный технический долг в UX.
- **Kimi Code CLI** — наиболее компактный по объёму активности; фокус на стабильности текущей версии, а не на новых фичах.
- **OpenCode** уникален мультипровайдерностью (GitLab DAP, Databricks, SAP AI, NVIDIA NIM) и наибольшим числом провайдерных хотфиксов, что отражает стратегию «поддержи всё».
- **Qwen Code** — единственный с явным CJK-первым подходом и наиболее быстрым циклом фикс→релиз (3 закрытых PR в тот же день).

## 5. Зрелость и активность сообществ

### 🏆 Наиболее активные сообщества

**Gemini CLI** — абсолютный лидер по объёму (46 Issues + 50 PR за сутки). Наличие структурированных эпиков (Remote Agents Sprint 1–3) и приоритизации (P1/P2) указывает на зрелый процесс управления беклогом. Однако объём нерешённых проблем сигнализирует о дефиците ресурсов на стороне команды.

**OpenCode** — сопоставим по PR-активности (50 PR), но с тревожным симптомом: сообщество прямо запрашивает AI-assisted code review из-за 1,6k необработанных PR. Высокая активность контрибьюторов при перегруженных мейнтейнерах — классический паттерн open-source проекта в точке перелома.

**OpenAI Codex** — 34 PR и 38 Issues при явных архитектурных PR от core-команды (меткие `@xl-openai`, `@charley-oai`, `@won-openai`). Разработка ведётся публично, что создаёт прозрачность, но обнажает незрелость отдельных подсистем.

### 🔄 В стадии быстрой итерации

**Qwen Code** — наиболее ритмичный цикл поставки: nightly-релиз + bump PR + 3 закрытых фикса за сутки. Команда реагирует на баги в течение часов, что редкость для инструментов такого класса.

**Claude Code** — реактивная модель: большинство PR инициировано сообществом в ответ на конкретные баги (RTL-регрессия, именование навыков). Core-команда менее публично вовлечена в трекер.

### 🐢 Осторожный рост

**Kimi Code CLI** — минимальная публичная активность: 4 Issues, 5 PR, 0 реакций мейнтейнеров на критические баги за сутки. Либо процесс разработки непубличный, либо ресурсы ограничены. Тем не менее наличие активных контрибьюторов (@CyCle1024, @hongquan) говорит о живом сообществе.

## 6. Трендовые сигналы

### 🔴 Сигнал 1: Мультиагентность переходит от концепции к инфраструктуре
Одновременная разработка Teams (Codex), Remote Agents (Gemini), Modes Layer (Qwen), GitLab DAP (OpenCode) — это не параллельные совпадения. Рынок консолидируется вокруг агентной оркестрации как стандартного примитива. **Вывод для разработчиков:** инвестиции в agent-to-agent протоколы (ACP, MCP) и resumable state management актуальны уже сейчас.

### 🔴 Сигнал 2: Windows — системная ахиллесова пята всей экосистемы
Нестабильность на Windows зафиксирована во всех пяти инструментах независимо от стека. Причины разные (virtiofs, EOL конвертация, TUI-рендеринг), но паттерн единый. **Вывод:** Windows-совместимость недооценивается командами при проектировании; первый инструмент, решивший её системно, получит конкурентное преимущество.

### 🟠 Сигнал 3: Headless/CI — следующий фронтир дифференциации
Запросы на корректный exit code, работающие Policy в неинтерактивном режиме, ретраи API-ошибок и поддержку XD

**Почему важно:** Зависание Task — критический дефект для пользователей, строящих агентные цепочки. Блокирует core-функциональность продукта. Открыт в день выхода дайджеста, реакции мейнтейнеров пока нет.

### 🔴 [#1293] Unable to communicate when using Kimi CLI on a remote SSH server
**[bug]** · Linux (headless) · v1.16.0

**Суть:** При использовании Kimi CLI на удалённом SSH-сервере без графического интерфейса и без возможности изменить системный DNS — CLI не может установить соединение. Проблема специфична для headless-окружений.

**Почему важно:** SSH/headless-серверы — типичная среда для ML-инженеров и DevOps. Неработоспособность в таком окружении ограничивает аудиторию продукта. Пересекается с открытым PR [#1236](#pr-1236) об `trust_env`.

Команда разработчиков оперативно реагирует — несколько PR уже закрыты с фиксами в тот же день.

## 4. 📦 Важные Pull Requests

### 🆕 Новый функционал

**[#1980](https://github.com/QwenLM/qwen-code/pull/1980) — Modes Layer: специализированные профили агентов**
Добавляет пакет `@qwen-code/modes` с `ModeManager`, `ToolRouter`, `PromptComposer` и 6 встроенными режимами: Architect, Code, Ask, Debug, Review, Orchestrator. Slash-команда `/mode` для переключения из CLI. Крупнейшее архитектурное изменение дня.

**[#2031](https://github.com/QwenLM/qwen-code/pull/2031) — VibeGuard-style client-side redaction**
Редакция секретов и PII прямо перед отправкой провайдеру: поддержка ключевых слов, regex и встроенных правил. Плейсхолдеры восстанавливаются локально в ответах модели. Важно для корпоративных пользователей.

**[#2018](https://github.com/QwenLM/qwen-code/pull/2018) — Поддержка `AGENTS.md` как контекстного файла**
`AGENTS.md` теперь распознаётся наравне с `QWEN.md` — out-of-the-box совместимость со стандартом [agents.md](https://agents.md/).

**[#1954](https://github.com/QwenLM/qwen-code/pull/1954) — Qwen Code в auxiliary sidebar VS Code**
Позволяет разместить чат в secondary sidebar для гибкой компоновки рабочей области.

**[#1975](https://github.com/QwenLM/qwen-code/pull/1975) — `qwen mcp enable/disable` команды**
CLI-управление MCP-серверами: включение/отключение по имени с поддержкой `--scope user|project`.

---

### 🐛 Исправления багов

**[#2029](https://github.com/QwenLM/qwen-code/pull/2029) — Алиасы `bash`/`sh` для shell tool** *(фикс #2012)*
Регистрирует `bash` и `sh` как алиасы `run_shell_command`, устраняя `Tool not found in registry` — один из наиболее часто воспроизводимых сбоев.

**[#2027](https://github.com/QwenLM/qwen-code/pull/2027) — Trim пробелов в именах skill** *(фикс #2025)*
`validateToolParams` теперь обрезает пробелы вокруг имени skill, предотвращая infinite loop при Chinese-именах.

**[#2028](https://github.com/QwenLM/qwen-code/pull/2028) — PDF → текст в functionResponse для Gemini** *(фикс #2020, CLOSED)*
Конвертирует PDF-части в текст перед отправкой в API, исключая каскадный отказ сессии после ошибки 400.

**[#2021](https://github.com/QwenLM/qwen-code/pull/2021) — Защита от усечённых tool call outputs**
Определяет ситуацию, когда DashScope/Qwen возвращает `finish_reason: "stop"` вместо `"length"` при достижении `max_tokens`, предотвращая молчаливую запись повреждённых данных.

**[#2007](https://github.com/QwenLM/qwen-code/pull/2007) — Санитизация `\r\n` в terminal output** *(фикс #1950)*
Убирает Windows-style line endings из вывода инструментов, устраняя визуальное смещение в Ink-интерфейсе.

## 5. 📈 Тренды запросов

### 🔴 Критический: Обработка китайского текста
Сразу 3 отдельных issue (#2032, #2025, #1964) и 2 PR (#2027, #2005) касаются одной проблемы: модель некорректно вставляет пробелы между китайскими символами и другими символами. Это системный паттерн, а не единичные случаи.

### 🟠 Архитектура агентов и мультиагентность
PR #1980 (Modes Layer), #1782 (visibility skills для subagent), #1993 (language context в subagent system prompt) — сообщество активно строит инфраструктуру для специализированных агентов и мультиагентных пайплайнов.

### 🟡 UX аутентификации и монетизация
Issues #1983, #2016 и PR #2030 указывают на системную проблему: пользователи не понимают разницу между free-tier и Coding Plan, а интерфейс `/auth` не помогает. Команда уже готовит редизайн.

### 🟢 IDE-интеграция (VS Code)
PR #1954 (auxiliary sidebar), issue #2023 (`/insight` в VSCode), PR #1817 (DNS-fix для Docker-окружений) — стабильность и полнота VS Code Companion остаётся приоритетом.

### 🔵 Безопасность и локализация
PR #2031 (VibeGuard-редакция) и issues #2022/#2023 (локализация `/insight`) показывают рост запросов на enterprise-ready функции.
