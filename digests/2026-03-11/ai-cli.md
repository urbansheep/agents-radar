## 1. Панорама экосистемы

Рынок AI CLI-инструментов находится в фазе конвергентного роста: все пять платформ одновременно развивают схожие примитивы — хуки жизненного цикла, агентные подрежимы (plan mode), плагинные маркетплейсы и механизмы управления контекстом. Экосистема демонстрирует нарастающее давление в сторону стандартизации: появление `AGENTS.md` с 3142 👍 в Claude Code — индикатор того, что разрозненные форматы конфигурации агентов становятся операционной проблемой в мультиагентных командах. Параллельно все инструменты испытывают системные трудности с кроссплатформенностью: Windows и WSL стабильно генерируют непропорционально высокую долю критичных багов. Зрелость отдельных платформ существенно различается — от стабильных CLI со сложившимся сообществом (Claude Code, Codex) до активно итерирующихся инструментов с видимыми QA-пробелами (Qwen Code, OpenCode). Фокус сообщества смещается от базового «chat-to-code» к долгосрочным агентным сессиям, что обнажает новый класс инфраструктурных проблем: утечки ресурсов, управление контекстом, надёжность при сетевых сбоях.

## 5. Зрелость и активность сообществ

### По зрелости (убывание)

**🥇 Claude Code** — наибольший объём community-активности (3142 👍 на один issue), самый крупный плагинный маркетплейс, высокая частота сторонних PR. Однако регрессии v2.1.69 и пробои в permission-модели сигнализируют о QA-долге при масштабировании.

**🥈 OpenAI Codex** — зрелая архитектура (Rust-core, WebSocket healthcheck, OTLP tracing), 6 релизов за день говорят о зрелом CI/CD. Проблема: стабильность соединения стала системным барьером для западных и WSL-пользователей.

**🥉 Gemini CLI** — высокая дисциплина релизного процесса (stable + preview ветки, cherry-pick bot), активная команда maintainers. Subagents-архитектура — технически наиболее продуманная из всех инструментов.

### По скорости итерации

**🚀 Kimi Code** — наиболее сфокусированный темп: 1 релиз с 3 значимыми изменениями, быстрое закрытие issue-feedback (Plan Mode выпущен вслед за feature request #1381). Response time команды — лидерский.

**🔄 Qwen Code** — агрессивный roadmap (v0.13.0: hooks, arena, daemon), но накопленный Windows-долг создаёт риск: новые фичи на нестабильном основании.

**⚠️ OpenCode** — высокая активность PR (50 за день), но отсутствие релиза при накопленных регрессиях (TUI в tmux, Tool.define() overflow) указывает на дефицит release governance.

## 6. Трендовые сигналы

### 📐 Стандартизация конфигурации агентов — неизбежна
`AGENTS.md` vs `CLAUDE.md` vs `GEMINI.md` — отраслевая фрагментация, которая уже болит. 3142 👍 за унификацию в Claude Code — беспрецедентный сигнал. Команды, строящие мультиагентные системы **сегодня**, должны закладывать абстракцию над форматами конфигурации или ставить на `AGENTS.md` как де-факто стандарт.

### 🔒 Permission-модели не готовы к production-автономии
Сразу в трёх инструментах зафиксированы обходы заявленных safeguard'ов (Claude Code #33106, #33126; Gemini CLI #21596, #21901; Codex Guardian Assessment в разработке). По мере роста автономности агентов это превращается из UX-проблемы в security-риск. **Разработчикам enterprise-решений** следует проводить независимый аудит permission-слоя, не полагаясь на декларации.

### ⚡ Долгосрочные сессии обнажают новый класс инфраструктурных багов
Утечки `/tmp` (OpenCode #16996, Claude Code #8856), накопление обёрток инструментов (OpenCode #16949, ~1000 шагов → RangeError), OAuth-истечение в CI/CD (Claude Code #12447) — все эти баги невидимы при коротких сессиях. Рост интереса к агентным воркфлоу делает lifecycle-менеджмент критичным требованием.

### 🌍 Windows — недофинансированная платформа с растущей аудиторией
Все шесть инструментов имеют непропорционально высокую долю Windows-багов при очевидно недостаточном Windows-тестировании. Это разрыв между реальной аудиторией (корпоративные разработчики на Windows) и целевым окружением разработчиков (macOS ARM). **Первый инструмент**, системно закрывший Windows-паритет, получит значимое конкурентное преимущество в enterprise.

## 5. Тренды запросов

### 🔌 Стабильность соединения
Наибольшее число горячих issues (#14048, #14209, #13245, #14297, #14317) вращается вокруг одной проблемы: **Reconnecting-петли и зависания**, особенно острые на Windows/WSL и для европейских пользователей. Это системная боль, не решённая даже в `0.114.0`.

### 🪝 Расширяемость и хуки
Релиз базового hooks engine в `0.114.0` и PR на динамические tool providers (#14246) отражают устойчивый запрос на **программируемую расширяемость** агента. Issue #2109 с 486 👍 остаётся лидером wishlist уже 7 месяцев.

### 🖥️ Кроссплатформенность
Три независимых кластера: **macOS Intel** (#10410, 147 👍), **Windows Desktop** (#14148, #14309) и **Zellij/TUI** (#2558, #9115) — указывают на системный дефицит тестирования non-ARM/non-macOS окружений.

### 🤖 Управление моделями и лимитами
Внезапное ограничение `gpt-5.3-codex` и `gpt-5.4` без уведомления (#14238, #14306) и появление нового `gpt-5.4-xhigh` режима создают **неопределённость вокруг модельного меню**, особенно для платных подписчиков.

### 🏢 Enterprise-функции
PR на кастомные CA (#14178), plugin policies (#14305) и requirements.toml (#14304) формируют отчётливый тренд на **enterprise-hardening** — корпоративную аудиторию с прокси, управляемыми конфигами и политиками безопасности.

# Дайджест активности Kimi Code CLI — 11 марта 2026

---

## 1. Обзор дня

Сегодня вышел релиз **v1.19.0**, включающий три крупных изменения: режим планирования (Plan Mode), систему визуализации сессий (`kimi vis`) и фикс WebSocket-шторма. Параллельно сообщество активно реагировало на критический баг с ACP `TerminalHandle`, затрагивающий пользователей v1.17–v1.18, а команда закрыла сразу несколько PR за один день, что свидетельствует о высоком темпе разработки. Зафиксировано 11 PR и 9 Issues за последние 24 часа — один из наиболее насыщенных дней за последнее время.

## 2. Релизы

### v1.19.0
📦 [Релиз на GitHub](https://github.com/MoonshotAI/kimi-cli/releases/tag/1.19.0)

| Изменение | Тип | Автор |
|---|---|---|
| Фикс WebSocket reconnection storm в session stream | 🐛 bugfix | @YoungY620 |
| Система визуализации трассировки сессий (`kimi vis`) | ✨ feature | @RealKai42 |
| Добавлен Plan Mode | ✨ feature | @RealKai42 |

**Ключевые детали:**
- **Plan Mode** — новый режим, в котором LLM ограничен read-only исследованием кодовой базы и записью в специальный план-файл. Активируется командой `/plan`, переключается через `Shift-Tab`. Требует явного подтверждения пользователя (`ExitPlanMode`) перед любым изменением кода.
- **`kimi vis`** — новая подсистема с FastAPI-бэкендом и React-фронтендом для визуализации wire-событий, контекстных сообщений и статистики сессий. Закрывает запросы на отладочную наблюдаемость.
- **WebSocket fix** — устранён каскадный реконнект в хуке `useSessionStream`, вызванный нестабильными цепочками зависимостей в `useCallback`.

## 3. Горячие Issues

**1. TUI сломан в tmux после v1.2.17**
🔗 [#16351](https://github.com/anomalyco/opencode/issues/16351) | 👍 12 | 💬 20
Наиболее обсуждаемый баг дня. После v1.2.17 в tmux текстовый ввод рендерится как серый прямоугольник, клавиатурные шорткаты не работают, мышь инжектирует сырые SGR-последовательности. Корневая причина, по словам автора, установлена. Высокая реакция сообщества указывает на широкое распространение.

**2. Преждевременная компактизация на GPT 5.4**
🔗 [#16333](https://github.com/anomalyco/opencode/issues/16333) | 👍 4 | 💬 10
GPT 5.4 поддерживает ~1M токенов контекста, однако компактизация срабатывает на уровнях, характерных для GPT 5.2. Баг существенно снижает ценность длинного контекста новой модели.

**3. ChatGPT не работает в v1.2.24 (Windows)**
🔗 [#16851](https://github.com/anomalyco/opencode/issues/16851) | 💬 9
`gpt-5.3-codex` возвращает `Bad Request` — модель не поддерживается через ChatGPT-аккаунт. Сигнализирует о проблеме несовместимости между версиями API и логикой выбора модели в клиенте.

**4. Bad Request при компактизации (Claude Opus 4.5, GitHub Copilot)**
🔗 [#13533](https://github.com/anomalyco/opencode/issues/13533) | 👍 2 | 💬 6
Компактизация обрывается с `Bad Request` при использовании Claude Opus 4.5 через интеграцию с GitHub Copilot. Дополнительно: Opus 4.6 недоступен в GitHub Enterprise Copilot.

**5. Несовместимые reasoning-параметры для openai-compatible провайдеров**
🔗 [#16154](https://github.com/anomalyco/opencode/issues/16154) | 💬 6
При использовании кастомных провайдеров через `@ai-sdk/openai-compatible` с моделями `gpt-5*` OpenCode отправляет `reasoningSummary` и аналогичные параметры, несовместимые с большинством OpenAI-совместимых бэкендов.

**6. Неустановленные VS Code-расширение: неоднозначные инструкции**
🔗 [#10517](https://github.com/anomalyco/opencode/issues/10517) | 👍 10 | 💬 3
Автоматическая установка плагина VS Code не работает у многих пользователей. Высокий рейтинг (👍 10) говорит о системной проблеме с документацией по IDE-интеграции.

**7. Утечка /tmp-артефактов при длительных сессиях**
🔗 [#16996](https://github.com/anomalyco/opencode/issues/16996) | 💬 1
В `/tmp` накапливаются файлы вида `.589<hex>-00000000.so`, способные исчерпать дисковое пространство при длительном использовании CLI. Критично для серверного использования.

**8. Tool.define() накапливает обёртки — RangeError после ~1000 шагов агента**
🔗 [#16949](https://github.com/anomalyco/opencode/issues/16949) | 💬 1
На каждом шаге агента `init()` добавляет новый слой обёртки к инструментам-объектам. После ~1000 шагов стек переполняется с `RangeError`. Критичный баг для долгосрочных агентных сессий.

**9. Ошибки инструментов теряют стек-трейс**
🔗 [#16925](https://github.com/anomalyco/opencode/issues/16925) | 💬 1
`processor.ts` преобразует ошибки инструментов через `.toString()`, уничтожая `.stack`. Диагностика сбоев в продакшне существенно затруднена.

**10. Rate limit не вызывает авто-retry — задача завершается немедленно**
🔗 [#16994](https://github.com/anomalyco/opencode/issues/16994) | 💬 1
При превышении лимита запросов OpenCode немедленно завершает задачу вместо автоматического повтора с задержкой. Ухудшает опыт работы с нагруженными API-эндпоинтами.

## 4. Важные Pull Requests

**🔧 Исправления (Bugfixes)**

1. **[#2277](https://github.com/QwenLM/qwen-code/pull/2277) — fix(core): сохранение CRLF при редактировании файлов** (@howardpen9)
   Критический фикс для Windows: edit-инструмент теперь восстанавливает `\r\n`-окончания после нормализации. Без этого патча каждое редактирование генерировало гигантский git diff.

2. **[#2268](https://github.com/QwenLM/qwen-code/pull/2268) — fix: `/export` использует ID текущей сессии** (@pomelo-nwu)

3. **[#2280](https://github.com/QwenLM/qwen-code/pull/2280) — fix: корректная JSON Schema для hooks** (@xuewenjie123)
   VS Code показывал type-ошибки при конфигурировании хуков в `settings.json` — патч устраняет некорректное определение типов.

4. **[#2221](https://github.com/QwenLM/qwen-code/pull/2221) — fix(core): отключение openDiff в YOLO-режиме** (@qqqys)
   В YOLO-режиме diff-редактор VS Code открывался без необходимости. Теперь `edit` и `write_file` не триггерят `ideClient.openDiff()`.

5. **[#2259](https://github.com/QwenLM/qwen-code/pull/2259) — fix(test): корректная обработка thinking-модели в E2E-тестах** (@wenshao)

6. **[#2275](https://github.com/QwenLM/qwen-code/pull/2275) — feat: daemon-режим с веб-интерфейсом** (@wenshao)

   Закрыта давняя feature-request [#1390](https://github.com/QwenLM/qwen-code/issues/1390): чат-UI теперь доступен в Activity Bar, нижней панели и Secondary Side Bar. Поддержка drag-and-drop.

   Arena запускает одну задачу параллельно на нескольких AI-моделях через изолированные git worktrees, позволяя сравнивать результаты и мержить лучшее решение.
