## 1. Панорама экосистемы

Экосистема AI CLI-инструментов переживает синхронный переход от индивидуальных ассистентов к компонентам мультиагентных систем: каждый из пяти инструментов в тот или иной форме работает над A2A-коммуникацией, MCP-интеграцией или агентными подпротоколами. При этом скорость выпуска новых возможностей системно опережает стабилизацию фундамента — Windows-совместимость, корректная работа с Unicode и предсказуемое поведение контекстного окна остаются нерешёнными проблемами сразу у нескольких игроков. Конвергенция вокруг стандарта `AGENTS.md`/`.agents/skills` становится первым реальным сигналом отраслевой стандартизации — issue #6235 в Claude Code (3048 👍) и параллельные запросы в Qwen Code и Kimi CLI свидетельствуют о том, что рынок давит на вендоров в сторону интероперабельности. Зрелость инструментов существенно расходится: Gemini CLI и OpenAI Codex ведут архитектурную работу корпоративного масштаба (gRPC, guardian approval, feature lifecycle), тогда как Kimi Code и Qwen Code занимаются стабилизацией базовых API-контрактов.

0 релизов, 3 PR, критическая «эпидемия 400-ошибок» без публичного ответа команды. **Вывод:** наименее активная фаза в выборке; команда, вероятно, занята серверной стороной.

### 🥇 1. `shodh-memory` — Персистентная память для AI-агентов
**PR #154** | Автор: @varun29ankuS | [Открыть на GitHub](https://github.com/anthropics/skills/pull/154)
**Статус:** 🟡 OPEN | Активность: дек. 2025 → март 2026 (75+ дней)

**Функция:** Реализует систему долгосрочной памяти между сессиями — агент вызывает `proactive_context` на каждое сообщение пользователя, структурирует воспоминания с богатыми метаданными и восстанавливает контекст при следующем запуске.

## 6. Боли разработчиков

**1. Контекстное окно — "ложь" системы**
Пользователи платят за модели с 1M-контекстом, но получают обрыв на 200K. Проблема воспроизводится на Anthropic Max, Amazon Bedrock и OpenAI. Корень — неверные данные в `models.dev` и отсутствие per-provider override.

**2. Windows — зона нестабильности**
Помимо антивирусных ложных срабатываний: самоудаление при быстром выходе (#16354), "bad request" при запуске агента (#16350), проблемы с запуском нескольких сессий (#16307). Windows-пользователи системно недообслужены.

**3. Модель сбрасывается сама**
Issue #12250 и китайскоязычный #16260 описывают одно: после отправки сообщения модель переключается обратно на дефолтную. Баг существует как минимум с v1.1.48 и не закрыт.

**4. Права доступа (permissions) не работают**
Конфигурация `permission` в `opencode.json` игнорируется (#16331) — прямая угроза безопасности для пользователей, ограничивающих доступ к `.env` и конфигам.

**5. LSP — утечка диагностики между проектами**
`LSP.diagnostics()` агрегирует данные со всех активных LSP-клиентов без фильтрации по workspace (#16353), что засоряет контекст агента нерелевантными ошибками.

**6. Документация отстаёт от кода**
Конфиг LSP (`command` обязателен при `initialization`) не задокументирован (#16345). SDK-примеры не показывают кастомных агентов (#2716). Разрыв между возможностями и документацией растёт по мере ускорения релизного цикла.
