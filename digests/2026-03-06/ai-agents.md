Экосистема open-source AI-агентов находится в фазе интенсивного роста при одновременном давлении со стороны пострелизной нестабильности — практически у каждого проекта в выборке зафиксированы регрессии после недавних релизов. ## 3. Позиционирование OpenClaw

**Масштаб сообщества — вне конкуренции.** 140 issues и 500 PR за сутки — это в 3–10× больше, чем у ближайших конкурентов (NanoBot: 66 PR, PicoClaw: 289 PR, но с принципиально меньшей базой мейнтейнеров). Количество смерженных PR за день (41) сопоставимо с PicoClaw, но при значительно более высоком абсолютном потоке.

**Технический подход.** OpenClaw демонстрирует наиболее зрелую архитектуру провайдерной абстракции: одновременно идут PR на GPT-5.4 Codex, MiniMax TTS и интеграции мессенджеров, что указывает на устоявшийся extensibility-слой. TUI как первоклассный интерфейс (не только веб) отличает проект от LobsterAI и EasyClaw, ориентированных на GUI.

**Дисциплина контрибьюций.** XS/S-патчи как доминирующий паттерн (изолированные фиксы по одной проблеме) — признак зрелого contribution guide. Zeroclaw и NanoClaw идут тем же путём, NanoBot и PicoClaw пока нет.

**Риски позиционирования.** Официальный отказ от i18n при очевидном спросе со стороны китайского сегмента (issues на китайском, запросы на Feishu/Kimi/GLM) — уязвимость, которую конкуренты с китайскими корнями (LobsterAI, NanoBot, EasyClaw) закрывают по умолчанию. Очередь в 459 PR — потенциальный сигнал для контрибьюторов о высоком барьере попадания кода в main.

## 5. Дифференциация

**OpenClaw** — платформенный универсал с наибольшим охватом провайдеров и каналов. Фокус на TUI и CLI, зрелая contribution-культура, но явный дефицит в китайской локализации.

**Zeroclaw** — Rust-first с акцентом на безопасность supply chain. Единственный проект, где security-hardening (SSRF, shell injection, panic isolation) является доминирующим треком дня. Целевая аудитория — production-окружения с требованиями к безопасности.

**IronClaw** — наибольшая инженерная дисциплина: E2E-тесты как первоклассный deliverable, structured release process, breaking-changes через семантическое версионирование. Ближе к «корпоративному» стандарту качества.

**LobsterAI** — китайский рынок как first-class citizen: Netease NIM, Feishu-боты, UTF-8 в планировщике. Skill Store и MCP в одном релизе — амбициозный продуктовый scope.

**NanoBot** — Python-экосистема, высокий темп контрибьюций, но системная нестабильность: «агент говорит, но не делает» как хроническая проблема агентного цикла.

**PicoClaw** — embedded-first (RISC-V, 256MB RAM, Sipeed LicheeRV). Единственный проект с явной аппаратной специализацией. JSONL-персистентность и токен-трекинг в контейнерах — специфика embedded production.

**EasyClaw** — форк/редеривация с фокусом на китайскую аудиторию (Bailian, Qwen, Kimi), закрытая разработка без публичных PR. Ранняя стадия, высокий migration debt.

**NanoClaw** — skills-маркетплейс как архитектурная ставка. Наибольшее количество community-contributed skills за день; opt-in паттерн в нескольких PR говорит о production-ориентированных контрибьюторах.

**TinyClaw** — ранняя стадия с архитектурными амбициями (multi-agent PR #163 — 35 файлов). Нулевое тестовое покрытие при растущем adoption — наибольший технический риск в выборке.

**Стадия стабилизации** (высокая активность, фокус на качестве):

- **OpenClaw** — стабилизация после конкретного релиза (2026.3.2), дисциплинированный процесс, но горлышко ревью.
- **IronClaw** — наиболее зрелый процесс: тесты как первоклассный deliverable, structured triage, чёткий roadmap релизов.

**Стадия быстрой итерации** (рост фич, нестабильность):

- **NanoBot** — высокий темп PR, но системные баги без фиксов (SIGHUP на Windows, Feishu event loop).
- **NanoClaw** — skills-экосистема растёт быстрее, чем ревью-мощность; OOM-баг без merge — тревожный сигнал.
- **LobsterAI** — крупный релиз v0.2.0 с потерей данных при апгрейде; активная пострелизная реакция, но migration story не продумана.
- **PicoClaw** — 248 PR в очереди при двух критических unfixed багах (дедлок, race condition) — разрыв между шириной и глубиной.

**Стадия кризиса/турбулентности**:

- **Zeroclaw** — релизный инцидент (v0.1.8 без бинарей) + публичное признание внутренних проблем. Краткосрочный кризис при сохраняющемся инженерном качестве в feature-треке.

**Ранняя стадия**:

- **EasyClaw** — закрытая разработка, 0 публичных PR, migration debt с первого минорного релиза.
- **TinyClaw** — 0 тестов, 0 смержённых PR за день; потенциал есть (multi-agent PR), инфраструктура отсутствует.

## 7. Трендовые сигналы

**1. Multi-agent как следующий обязательный примитив.** Пять проектов одновременно ведут архитектурные работы по координации агентов (Zeroclaw Phase 1, TinyClaw PR #163, PicoClaw Swarm Mode, NanoBot Steering Loop, IronClaw ApprovalContext). **3. Экономика токенов определяет архитектурные решения.** Запросы на локальные LLM (Ollama, vLLM) мотивированы явно экономически («агент потребляет много токенов»). Это давление будет только расти; проекты без надёжной Ollama-интеграции теряют cost-sensitive

## 7. Фидбек пользователей

### Основные боли

**Дедлок в pool.go при панике фабрики**
[Issue #1150](https://github.com/sipeed/picoclaw/issues/1150) | `priority: high` | автор @drpedapati

Если `p.factory(target)` в `pkg/routing/pool.go` паникует, ключ не удаляется из `p.creating` и `inflight.done` не закрывается. Результат — **постоянный дедлок** для данного target. PR с исправлением не обнаружен. Требует срочной реакции мейнтейнеров.

[Issue #1151](https://github.com/sipeed/picoclaw/issues/1151) | `priority: high` | автор @drpedapati

`phiSetLocalDefaultsCmd` выполняет read-modify-write `config.json` в горутине `tea.Cmd`, конкурируя с другими табами TUI (settings, login, routing). Возможна **порча конфигурации** при одновременных изменениях.

**Issue [#160](https://github.com/TinyAGI/tinyclaw/issues/160) — Ложное сообщение об обновлении в CLI**

- **Симптом:** CLI сообщает `Current: v0.0.8 → Latest: v0.0.9`, хотя пользователь уже использует актуальную версию.
- **Причина:** Тег `v0.0.9` и `package.json` (версия `v0.0.8`) не синхронизированы в репозитории.
- **Влияние:** Затрагивает всех пользователей CLI, создаёт путаницу при обновлении.
- **PR с исправлением:** ✅ [#161](https://github.com/TinyAGI/tinyclaw/pull/161) открыт, ожидает ревью.
  - Решение: добавление guard-шага в GitHub Actions, блокирующего релиз при несоответствии версий.

### 🟡 Системный риск (не баг, но потенциальный источник регрессий)

**Issue [#162](https://github.com/TinyAGI/tinyclaw/issues/162) — Отсутствие автоматизированных тестов**

- Полное отсутствие тестового покрытия при активном добавлении функциональности (см. PR [#163](https://github.com/TinyAGI/tinyclaw/pull/163)) существенно повышает риск скрытых регрессий.
- Сборка релизов только под Ubuntu создаёт риски несовместимости на macOS и Windows.
